# Модульный фреймворк автоматизации тестирования для интернет-магазина Pas Normal Studios

## 📝 Описание проекта
Данный проект представляет собой высокоуровневый автоматизированный фреймворк для сквозного (End-to-End) тестирования функционала международного интернет-магазина премиальной велоодежды `pas-normal-studios.com`. Архитектура спроектирована на языке **Java 21** с использованием объектно-ориентированного подхода **POM (Page Object Model)** в соответствии с принципами чистого кода **SOLID**.

## 🏗 Архитектура проекта и паттерны проектирования
Фреймворк разделен на независимые архитектурные слои согласно принципу **Single Responsibility (SRP)**, что гарантирует масштабируемость системы и чистоту кода.

**Слой управления сессией браузера (`com.pasnormalstudios.driver`)**
* **Singleton Pattern (`Driver.java`)** — гарантирует существование строго одного инстанса `WebDriver` (ChromeDriver) на протяжении выполнения теста, изолируя сессии и предотвращая утечки памяти.

**Инфраструктурный слой страниц (`com.pasnormalstudios.pages`)**
* **`BasePage.java`** — аккумулирует базовую конфигурацию страниц, содержит защищенный логгер и инициализирует явные ожидания `WebDriverWait` для безопасного взаимодействия с веб-элементами.

**Бизнес-слой страниц (`com.pasnormalstudios.pages`)**
* **`HomePage.java`, `AccountPage.java`, `ResetPasswordPage.java`** — инкапсулируют логику стартовой навигации, авторизации и восстановления пароля.
* **`CartPage.java`, `ProductPage.java`, `SearchPage.java`** — содержат логику поиска и добавления товара в корзину. Используют Java Stream API для фильтрации элементов.

**Слой тестовых данных (`com.pasnormalstudios.data`)**
* **Factory Pattern (`Users.java`, `Products.java`)** — фабрики для генерации тестовых сущностей (через Datafaker или базовые DTO).
* **DTO (Data Transfer Object)** — класс `Product` используется как единая модель данных. Страницы (например, `CartPage`) парсят UI и возвращают готовые объекты `Product` для последующего сравнения бизнес-сущностей целиком.

**Слой проверок (Assertions)**
* Использование **AssertJ** для глубокого рекурсивного сравнения сложных объектов (`usingRecursiveComparison().isEqualTo()`). Это позволяет сравнивать состояние UI с эталонными данными в одну строку кода и получать максимально информативные отчеты об ошибках.

## 📊 Тестовое покрытие

### 💻 UI Тестирование (`com.pasnormalstudios.ui`)
* **Комплексная разметка Allure:** Тесты аннотированы тегами `@Epic`, `@Feature`, `@Story`, `@Severity` и `@DisplayName` для генерации структурированной документации.
* **`AccountTest.java`, `ResetPasswordTest.java`**: Сквозные проверки аутентификации, регистрации и валидации форм.
* **`CartTest.java`**: Тестирование E-Commerce ядра. Проверка добавления товаров, работы поисковой выдачи, выбора размеров/цветов и точного соответствия свойств товара в корзине.

### 🔌 API Тестирование (`com.pasnormalstudios.api`)
* **`AccountTest.java`**: Тесты интеграции и валидации бэкенд-эндпоинтов аутентификации. Слой `ApiService` использует Rest-Assured для отправки POST-запросов и проверки статус-кодов.

## 📈 Логирование и Тестовая отчетность
* **Allure Framework:** Полная интеграция с JUnit 5. Отчеты предоставляют пошаговую детализацию прохождения UI и API тестов с понятным описанием каждого шага.
* **Log4j2 (Конфигурация `log4j2.xml`):** Прозрачное логирование действий. Логи пишутся в консоль (`Console Appender`) и в файл (`File Appender` в `logs/app.log`).
* **Логирование API и UI-трафика:** `ApiService` автоматически перехватывает HTTP-запросы, а методы в Page Objects логируют поиск и взаимодействие со сложными элементами интерфейса.

## 🚀 Команды для запуска

Запуск всех тестов проекта (UI и API тестов) с автоматическим сбором результатов:
```bash
mvn clean test
```
